# Developer Profile

## About Me

I am a junior developer with about a year of software development experience, coming from a mathematics background with a master's degree in mathematics. I am transitioning into full-stack web development and tend to learn best by breaking complex ideas into smaller, logical steps. I care a lot about understanding how things work, not just getting something working quickly.

I am especially interested in building systems and tools that improve how developers think, learn, and work, not just how fast they can produce code.

## Tech Stack

- **Languages:** HTML, CSS, JavaScript, Python, SQL
- **Frontend:** React
- **Backend:** Django
- **Data:** SQL, relational databases
- **API / Web:** RESTful APIs
- **AI Tools:** Claude, ChatGPT, Codex
- **Version Control:** Git, GitHub

## Development Philosophy

- AI can help me move faster, but I still want to understand what gets built and why.
- I prefer practical solutions over trendy ones, and I want abstractions to make sense before I trust them.
- I learn best when things are explained clearly and tied back to the real code or problem being solved.
- I want to build a strong long-term foundation, not just chase quick wins.

## Strong Skills

- Designing structured workflows and systems for learning and development (e.g., Tandem command system)

## How I Like to Work

- I prefer to work step-by-step rather than seeing everything at once.
- I like to understand the reasoning before writing code.
- I prefer being asked whether I want to implement something or have it shown to me.
- I do not want large blocks of code without explanation.
- I learn best when explanations are tied directly to the code I am working on.
- If something is unclear, I prefer being asked rather than having assumptions made.

## What to Avoid

- Do not over-explain simple concepts I already understand.
- Do not use overly polished or generic language.
- Do not introduce unnecessary abstractions early.
- Do not rewrite large sections of code without explaining why.
- Do not assume intent when requirements are unclear.

## Explanation Preferences

- Start with a high-level explanation, then go deeper if needed.
- Use concrete examples instead of abstract explanations.
- Focus on why decisions are made, not just what is being done.
- Keep explanations practical and connected to real code.

## Workflow Preferences

- Break work into small, clearly defined steps.
- Show the full plan before starting when possible.
- Confirm direction before making larger changes.
- Prefer iterative progress over large one-time outputs.

## Tooling Preferences

- Prefer lightweight tools over heavy or resource-intensive ones.
- Prefer DBML for ERDs instead of Mermaid diagrams.
- Prefer simple, readable formats over complex visualizations unless needed.
